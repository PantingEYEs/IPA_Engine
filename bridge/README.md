# IPA LatinIME read-only bridge

Copyright (c) 2026 PantingEYEs. All rights reserved. No project license has been selected for these independently written adapter files. Upstream HeliBoard / Android source files keep their original notices and licenses. This adapter calls the pinned upstream core API directly; it does not compile the upstream JNI registration files or reproduce the previous IPA Board Java declaration classes.

## Library and identity

`libipa_latinime.so` exports only the six JNI methods in `org.ipaboard.latinime.LatinImeNative`. The Java class loads that library and rejects an ABI version other than 1. The generated `build_identity.h` is required: there is no unversioned fallback.

`identity()` returns standard UTF-8 bytes in this exact field order:

```
ipa-latinime;abi=1;packet=1;heliboard=4.1;source=<upstream revision>;dictionary=<dictionary SHA-256>;build=<source and recipe build ID>
```

An application should compare every field with the artifact manifest before opening a dictionary. A matching library filename alone is insufficient.

## Six entry points

- `int abiVersion()` returns 1.
- `byte[] identity()` returns the identity above.
- `long open(byte[] absoluteDictionaryPath)` opens one read-only dictionary and its native proximity map, returning an opaque positive owner handle.
- `byte[] query(long owner, byte[] input, byte[][] previousWords, boolean beginningOfSentence)` returns one owned packet. Previous words are nearest first. Each query gets a fresh traversal cache; zero input invokes upstream predictions.
- `int probability(long owner, byte[][] previousWords, boolean beginningOfSentence, byte[] word)` returns the upstream n-gram probability, or -1 when unavailable. Empty previous words with `false` request the independent probability.
- `void close(long owner)` releases that owner. This low-level method rejects double close; a higher-level AutoCloseable wrapper may make its own close idempotent.

No raw pointer is exposed. Handles increase monotonically and are never reused. At most eight owners may be open at once. All methods, including close, are serialized by one process-wide mutex; this also protects upstream static state. A call racing close either completes before close or fails with the stable invalid-handle exception. Owners must be explicitly closed in a finally block / owned lifecycle. An unsuccessful open does not publish a handle and releases partial allocations.

## Inputs and immutable dictionary precondition

All byte arrays are standard, well-formed UTF-8, never Java modified UTF-8, and must contain no NUL. Supplementary Unicode is accepted in paths, context words and probability words. Input strings are never logged by this adapter, and exceptions do not include paths or text.

- Dictionary path: absolute POSIX/Android path, 1..4096 UTF-8 bytes.
- Query spelling: 0..47 ASCII letters or apostrophes. ASCII capitals are folded to lowercase. No gesture or measured touch coordinates are supplied.
- Context: non-null array, 0..3 nonempty words, each 1..47 Unicode scalar values and at most 188 UTF-8 bytes. `beginningOfSentence=true` requires an empty context array and synthesizes the upstream BOS marker.
- Probability word: 1..48 Unicode scalar values, at most 192 UTF-8 bytes.

**The caller must verify the complete dictionary SHA-256 against the artifact manifest before opening it and keep the file immutable for the lifetime of all owners.** Native open checks the file type, bounded size, magic, format and header length; it is not a cryptographic validator or a general hostile-dictionary parser. It accepts only the pinned file-based binary format 202, not writable directory dictionaries. The bundled en_US dictionary has wordlist version 54, which is distinct from binary format 202. No dictionary learning, add/remove, flush, writable mapping or personalization API is exposed. No dictionary is generated by this adapter.

The native key map is the current IPA Board contract: a-z and apostrophe, no touch coordinates, edit-distance correction enabled, offensive-word blocking disabled, no gesture, locale weight 1.0 and a fresh small traversal cache. These are compatibility settings rather than configurable Android keyboard UI features.

## Packet version 1

The result is an owned Java byte array, independent of the next query or owner lifetime. Integers are little endian. The maximum packet size is 16 KiB.

| Header byte offset | uint32 value |
| --- | --- |
| 0 | magic `0x4c41544e` |
| 4 | packet version 1 |
| 8 | result count, 0..18 |
| 12 | complete byte-array size |
| 16 | entry size, 16 bytes |
| 20 | reserved, zero |

Entries begin at byte 24. Each has `int32 score`, `uint32 type flags`, `uint32 text offset`, `uint32 text byte length`. Texts follow the entries contiguously, with no padding or NUL terminators. Each text contains 1..48 valid Unicode scalar values. Offsets are absolute within the packet. A decoder should reject invalid UTF-8, unknown layout/version, unexpected reserved values, overlapping/gapped text ranges, oversized counts/lengths, and trailing bytes.

Scores and type flags are preserved from upstream. The core drains its queue in worst-first order; the application must order candidates by score descending (and its existing tie policy), not interpret packet position as rank. Casing, completion/correction classification, feature toggles, context affinity and common-word fallback remain application behavior.

## Errors

Invalid values produce `IllegalArgumentException` with `IPA_LATINIME_INVALID_ARGUMENT`. Owner/lifecycle and resource errors produce `IllegalStateException` with one of:

- `IPA_LATINIME_INVALID_HANDLE`
- `IPA_LATINIME_OWNER_LIMIT`
- `IPA_LATINIME_HANDLE_EXHAUSTED`
- `IPA_LATINIME_DICTIONARY_UNAVAILABLE`
- `IPA_LATINIME_DICTIONARY_FORMAT`
- `IPA_LATINIME_INVALID_NATIVE_RESULT`
- `IPA_LATINIME_INVALID_NATIVE_TEXT`
- `IPA_LATINIME_OUTPUT_TOO_LARGE`
- `IPA_LATINIME_NATIVE_FAILURE`

Allocation failure produces `OutOfMemoryError` / `IPA_LATINIME_ALLOCATION_FAILED`; pending Java exceptions are preserved. No C++ exception escapes JNI. Library/ABI load failures use the usual linkage error or `IPA_LATINIME_ABI_MISMATCH`.

## Source and validation boundary

This bridge is compiled and linked with one pinned HeliBoard source tree; it is not an ABI adapter for arbitrary external LatinIME builds. Only the generated identity and the six JNI symbols are public. Core classes are not a stable shared-library ABI.

The build and validation scripts record source hashes, exact artifact identity, exported symbols, both ABI ELF load alignment and runtime results. This interface description does not itself claim any test has passed. IPA Board-specific experimental adapters and old/new comparison harnesses remain in the private Board fixture tree rather than being relicensed into this standalone source branch.
