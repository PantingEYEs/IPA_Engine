# IPA 压缩词典的图结构选型

本轮从已有发音资料编译离线词典，原生核心在 Android 上按需查询，词频负责当前排序。默认压缩目标为 **30,000,000 字节**；用户已允许略超目标的比较包，因此同时提供完整 32 位索引版本，测量其体积和速度。30 MB 按十进制计算，不能用 30 MiB 或 APK 的 ZIP 体积替代。当前默认 24 位词典已低于该目标；运行时与 Android 资产加载的绝对上限为 40,000,000 字节。通用 GRU 训练工具和数值验证程序保留，旧权重已删除；后续可用于新模型实验。

当前选择是 **最小确定无环有限自动机（DAFSA，也常被称作词典 DAWG）+ 路径词典序编号 + 独立候选倒排表 + 分块前缀压缩词形池**。这里的 DAWG 指有限词集的无环接受器，不是用来索引任意子串的后缀自动机。最小化只改变结构，不删掉读音和词汇关系；轻声、声调、重音、长度和音节界限仍是键的一部分。

## 已有词典的形式化

SQLite 是资料库，包含原始观测、来源、频率语料和索引。设备实际需要的有限关系为：

```text
R ⊆ K × W × Region × Quality × Frequency
K = NFC(完整 IPA 字符串)
W = 完整上屏词形字符串
```

一个 IPA 对应多个词，一个词也可以有多个 IPA。中文上屏形式按地区选择现有 `simplified`/`traditional` 字段；地区不能由繁简字形推断。中英文同文、大小写变体、日语同音异字不应在词形池里被错误折叠。跨来源的重复观测可以合并为相同的可查询关系，完整来源仍保留在离线资料与构建报告中。

只收录宿主支持的输入与输出：本次整串 IPA 不超过 64 个 UTF-16 单元，输出非空白、不含孤立代理，且不超过 1,000 个 UTF-16 单元。非默认地区、非词/字类型和超过合同长度的记录必须在构建报告中计数。NFC 处理规范等价形式；不得改用 NFKC、删重音、删声调或把音节界限统一抹掉。若未来提供宽松发音模式，它应是显式别名或独立纠错图，不可伪装成严格精确命中。

频率是词形的先验，无法据此得知多音词某个读音的真实频率。`zipf` 与正的 `per_million` 可以换算到一致的参考尺度，再按现有最大证据启发式取值；不同来源的原始计数不能直接累加。运行包只保存有限精度排序分数，观测值和评分口径留在构建侧。这一分数量化有损，但 IPA→候选集合压缩可以无损，二者要分别验证。

## 为什么选择接受器加倒排表

DAFSA 将具有相同可接受后缀集合的状态合并。词典序输入可增量构建，避免必须先保留一个完整指针 Trie 再最小化。[Daciuk 等，2000](https://aclanthology.org/J00-1002/)

候选词形、地区或词频不能直接绑定在最小接受器的终态上：例如 `ab` 和 `cb` 可能共享终态，但两个键的候选集合不同。也不能把候选 ID 纳入状态等价条件，否则大量合法后缀共享会消失。本实现把候选记录绑定到**完整输入路径的词典序编号**。

设 `F(s)` 表示状态是否终止，按标签顺序排列的子状态为 `t₁…tₙ`。定义：

```text
C(s) = F(s) + Σ C(tᵢ)
```

查询从 `rank = 0` 开始。每次选择某条边之前，累加当前终态的 `F(s)` 和所有较小标签分支的 `C(tᵢ)`，再进入目标状态。完整键终止时的 `rank` 就是唯一的候选表索引。同一共享状态由不同前缀到达时累积编号不同，因此候选不会串词。前缀查询也能得到连续编号区间 `[rank, rank + C(s))`。

这相当于给已有键构造无碰撞的词典序编号，同时保留接受器对不存在键的拒绝能力。无需携带原始键字符串哈希表。子状态计数必须是**接受路径数量**，不能是可达不同状态数量；构建和读入端都应检查计数溢出。

## 与其他结构的比较

| 方案 | 对当前需求的优势 | 代价与本轮判断 |
| --- | --- | --- |
| 普通 Trie / radix Trie | 精确、前缀、遍历容易实现；radix 能合并单分支路径 | 只共享前缀，不能合并等价后缀；对象与指针布局浪费较多。适合作为构建基线，不选作当前设备文件格式。 |
| 双数组 Trie | 索引连续，查找直接，已有成熟实现 | 数组空位和 Unicode 标签布局依赖词集；必须另存多候选。尚未对本资料做同条件编译，不能声称其必定比 DAFSA 大。 |
| MARISA / succinct Trie | 静态紧凑 Trie；支持精确、反向、共同前缀和预测搜索，可 mmap | 很适合作为后续压缩基线；仍需独立多候选、频率与过滤数据。递归层数是大小/查询开销的取舍。没有本资料的实测，不能把其他数据集的压缩率直接套用。 |
| 最小 DAFSA + 倒排表 | 同时共享前后缀；一份 IPA 图承载中英日；精确集合无损；可给输入键计算编号 | 对前缀高频 top-k 需额外排序或索引；最小化不能自动解决同音歧义。当前只需要静态词典与词频，结构最直接。 |
| WFST + OpenFst | 能把发音、词汇、错误模型和语言模型组合，进行带权路径搜索 | 多输出映射仍需表达歧义；通用转导器和 semiring 运算对当前词频查询增加结构和依赖。保留为连续解码/模糊发音的后续路线。 |

MARISA 官方文档说明了查询方式、唯一 ID、mmap 与参数取舍；它是有价值的候选，不应因为用了 Trie 就排除。[MARISA 文档](https://www.s-yata.jp/marisa-trie/docs/readme.en.html)

WFST 是数学模型，OpenFst 是构建和操作它的库，两者不是不同级别的压缩手段。OpenFst 提供组合、确定化、最小化和最短路径，也有专门的 CompactFst/ConstFst 表示；不能笼统断言 OpenFst 只支持臃肿的对象图。当前选择来自功能范围和可控制的固定格式，而不是已经证明自研图比所有 CompactFst 都小。[OpenFst 概览](https://openfst.org/twiki/bin/view/FST/)、[表示类型](https://openfst.org/twiki/bin/view/FST/FstAdvancedUsage)、[CompactFst 官方接口](https://www.openfst.org/doxygen/fst/html/classfst_1_1CompactFst.html)

## 正式编译的实际结果

严格编译重新执行可收录性检查后得到 **1,024,289 个 IPA 键、768,387 个唯一词形、1,281,101 条候选地区映射**，138 个 IPA 字符。图为 **1,143,559 节点、1,867,683 边**；对应普通 Trie 为 5,289,813 节点。图本体 14,332,089 B，候选内容 6,847,047 B，前缀压缩词形内容 4,590,025 B，连同所有目录与表头的完整 24 位文件为 **28,986,769 B**。与上面的独立剖面略有差异，是因为正式编译重新检查了来源筛选和 IPA，不是尺寸裁词。

实际全 32 位文件为 **34,213,887 B**，比默认增加 5,227,118 B（18.03%）。它同时采用所有 32 位目录/计数与 5 字节边，没有填充；候选和词形内容完全相同。全量 `24 → 32 → 24` 转换已验证逐字节相等，两格式对独立抽取的 5,000 个键进行了完整候选参照比较。两版均保留，没有仅凭理论估算排除 32 位。

开发机五轮、每轮每格式对 5,000 个输入循环查询 100,000 次，24/32 位 p95 中位数为 0.001916/0.002250 ms，p99 为 0.002458/0.003000 ms，图验证与加载约 33.385/32.242 ms。包含预热、未控制文件页缓存，不含 JNI 和宿主调度；开发机证据支持先默认 24 位。S21 Ultra 实机与真实 AAR 资产测试另见 `data/reports/graph-s21-comparison.json`、`data/reports/android-wrapper-probe.json`，最终默认以实机对比为准。

这些候选一致性测试说明压缩关系得以保留，不是词典发音正确率或同音词首选命中率。当前只有五地区开关，派生读音属性会显示，但没有单独的运行时派生开关。

## 文件压缩手段

默认格式 v2 采用 **24 位小端整数表**：CSR 边起点和终态/路径计数各 3 字节，状态合计 6 字节；计数最高位表示终态，其余 23 位保存接受路径数。边以 4 字节保存，即 8 位 IPA 符号编号与 24 位目标节点。138 个字符可以编号为一个字节，约 114 万节点也在 24 位范围内。候选起点和词形块起点同样使用 24 位直接索引。实际图本体含 CSR 哨兵为 **14,332,089 字节**。

比较格式 v3 将四张索引/计数表全部改为 32 位，终态使用计数最高的第 31 位；每条边为 **5 字节**，即 8 位标签与 32 位目标，无对齐填充。它不是仅把部分数组变宽的旧估算基线。两种格式的 IPA 字符表、候选记录和词形压缩完全相同，原生核心从头部版本自动选择宽度。磁盘值均按小端字节读取，不能假定表格具有原生指针对齐。

24 位编译必须检查字符表不超过 **255**（标签 0 保留）、节点与各偏移小于 `2^24`、接受路径数小于 `2^23`。32 位版本相应使用 32 位偏移和 31 位路径计数。超限应拒绝构建或升级格式，不能截断。

候选表按输入键编号组织，候选按词形池 ID 排序。差分 ID 和地区/直接派生标志用 varint 保存，参考分数用单字节保存。相同词形只存一次，候选引用词形 ID。这样一个词的多读音不再复制整串 UTF-8 文本。

词形池按 UTF-8 词典序分块前缀压缩。每块第一词保留全文，其余保存与上一词的公共字节前缀长度和剩余后缀；读取一个候选最多重建固定数量的词。完整重建结果必须保持原字符串。独立剖面给出：

| 重启间隔 | 含 32 位分块索引的词形池 |
| --- | ---: |
| 8 词 | 5,246,247 字节 |
| 16 词 | 4,782,129 字节 |
| 32 词 | 4,549,886 字节 |
| 64 词 | 4,433,719 字节 |

仅候选词形 ID 的差分 varint 为 3,576,579 字节，另需地区/质量、分数、每键候选边界。图小于 30 MB 不代表整个词典小于 30 MB；必须对最终完整文件做硬性上限检查。

正式 24 位包的 16 词分块词形区含索引为 **4,734,103 字节**，候选记录区为 **6,847,047 字节**。完整文件的实际比较为：

| --- | ---: | ---: |
| 完整词典文件 | 28,986,769 字节 | 34,213,887 字节 |
| 相对 24 位包增量 | — | 5,227,118 字节，+18.03% |

`scripts/convert_graph_indices.py --index-bits 24|32` 只改整数宽度和终态位，不重扫 SQLite、不删候选。两版候选与词形区哈希相同；v2 → v3 → v2 可重建原文件 SHA-256。完整 32 位包允许超出 30 MB 比较目标，仍受 40 MB 绝对上限约束。[格式规范](../graph/format_spec.md)、[32 位编译清单](../data/compiled/lexicon-32.manifest.json)

当前使用 24 位直接索引，在满足预算时优先保持这项查询便利。如果未来增长导致全包超过 30,000,000 字节，可进一步采用**分块候选起点**：每 32 个键保存绝对起点，块内保存候选字节长度 varint，查一个键只需累计至多 31 个长度。相对未压缩的起点数组它可继续节省空间，不改变候选集合，也无需解压整个文件。后续才考虑状态起点分块编码、Elias–Fano 单调索引或边目标差分 varint。它们更省空间，但每次走边需要更多解码或 rank/select 操作，应通过 S21 Ultra 延迟实测决定。

设备宜直接映射或只读加载该紧凑图。ZIP/zstd 整包压缩适合传输，不保证可随机查找，整包展开也会使安装大小和常驻内存预算失去意义；若增加块压缩必须单独限制解压缓存。

## 24 位与 32 位的实测取舍

开发机在 5,000 个输入用例上预热，交替运行两种格式；每版运行 5 轮，每轮 100,000 次查询。下表是各轮指标的中位数，不是合并所有查询后重新计算的分位数。

| 原生核心指标 | 24 位 | 32 位 |
| --- | ---: | ---: |
| p95 查询耗时 | 0.001916 ms | 0.002250 ms |
| 加载及结构/UTF-8 验证耗时 | 33.385 ms | 32.242 ms |

本机热查询没有观察到 32 位优势；32 位的加载中位数稍低，却增加了约 18.03% 的完整词典体积，因此默认保留 24 位，保留已实测的 32 位对照包。操作系统页缓存没有清空，运行未隔离系统噪声，这些微秒级数字不能证明性能差异的原因，也不能推算 S21 Ultra 的延迟、热降频或耗电。加载时间不包含 Android 的资产复制、SHA-256 校验、JNI/JSON 转换和宿主调度。报告还包含 5,000 个独立 oracle 键、两版共 10,000 次结果比较；这些比较验证候选/排序实现一致性，不是用户意图识别准确率。[完整索引比较报告](../data/reports/graph-index-comparison.json)

## 连续输入与排序的边界

完整词典查询返回资料中的词形；它不保证首选就是用户意图，也不能修复源读音错误。源数据映射或压缩回读检查即使遍历所有可收录关系，证明的也只是**候选覆盖与结构保真**，不能称为中文/英语/日语准确率，更不是词频排序的首选准确率。语言质量需另建有人类目标词或真实输入意图的评价集，分别报告首选和前 N 候选命中。运行时最多返回 180 个去重候选，同音关系更多时不能把“存在于图中”等同于“必定出现在返回列表里”。

当前排序优先精确词候选，其后是补全；同类按量化词频、派生参考惩罚和稳定词形顺序排序。前缀存在大量扩展时，词典序前 N 个不是全局词频前 N 个。最小图共享状态的最高分也不能直接复用到不同前缀的候选集合。当前补全按词典序最多检查 `prefix_key_budget` 个键，达到预算则在诊断里标记 `truncated=true`，仅对已检查的键排序；过滤掉的地区也可能消耗遍历预算。若要保证前缀全局 top-k，需要候选编号区间的最大分索引或等价算法。

连续完整 IPA 后续可在输入位置 `0…n` 上建立**加权分词 DAG**：从每个位置遍历 DAFSA，每次遇到终态建立覆盖完整片段的候选边，最后寻找从 0 到 n 的路径。边只向后移动，因此词格无环，可用动态规划或有限束搜索找最佳完整路径。未来边代价可来自词频先验与经验证的切词惩罚；无上下文时仍会有歧义。所有候选必须消费整串，不能返回只转了前半段的结果。英语组合词间通常需要空格，中日组合形式和混语言边界应通过专门的拼接政策决定。源 IPA 内部空格不能一律删除。

这种按查询临时生成的格已经是有限带权图，不要求把所有句子预展开进设备词典。未来存在错误模型、词类约束或真实上下文模型时，再评估 OpenFst 的延迟组合和最短路径收益。当前“连续分词格”属于下一阶段方案，不能据选型文档声称已经实现。

未来训练的 GRU 可以用 teacher-forcing 计算字典候选的条件分数，与词频经过校准后重排。输出字符表缺字或模型未覆盖的候选不得因此从精确字典结果里删除。旧权重没有证明首选排序有稳定收益，已删除，当前继续按词频排序。新模型需在独立留出集测重排首选命中率及推理成本，训练和导出用法见 [模型训练工具](模型训练工具.md)。

## 验证要求与手机验收

编译验证应比较可收录 SQLite 关系与展开后的压缩关系，检查重复来源合并、地区过滤、派生 provenance、NFC、共享终态、超长输入和畸形文件。当前运行时只有五地区开关，未提供独立派生禁用开关。排序分数量化需要报告误差，图和词形压缩应保持集合相等。测试 CLI 应显示实际 IPA、政策、候选文本/语言/分数/类型、查询耗时与是否截断，并支持批量输入、JSONL 和交互观察。

三星 S21 Ultra 的实际 SKU/处理器和系统版本应由设备信息记录；官方不同地区资料也有不同芯片版本，不能把开发机结果称为 S21 Ultra 结果。[三星美国数据表](https://image-us.samsung.com/SamsungUS/samsungbusiness/pdfs/datasheet/Galaxy_S21_Series_Datasheet_Unlocked.pdf)、[三星地区产品目录](https://images.samsung.com/is/content/samsung/assets/iran/smartphones/mobile-catalogue/samsung-mobile-digital-catalogue-20211122-mob.pdf)

第一轮手机验收用 `arm64-v8a` 构建，记录冷启动和热查询 p50/p95/p99、常驻与峰值 RSS、字典映射、15–30 分钟输入/退格/语言切换后的资源变化、温度和耗电。图查询天然不需要后台持续计算；长期实时运行仍须设备实测。宿主 Messenger、路由和服务隔离继续遵循 `引擎开发规范.md`，静态库或 JNI 包不等于已修改 IPA Board 宿主。

## 本轮 S21 Ultra 实测决策

已连接 SM-G998U1（Android 15 / API 35）。同一 arm64 程序加载两格式，5,014 个输入的完整输出一致。5 轮交替运行，每格式共 500,000 次对照输入循环查询，无错误/超时；p95 各轮中位数 24 位 0.006979 ms、32 位 0.007292 ms，p99 为 0.030781/0.031562 ms。加载/验证约 70.376/67.806 ms，50 ms 抽样峰值 RSS 为 35,260/40,328 KiB。文件缓存未清空、含预热、不计 Java 与 UI；RSS 包含驻留映射页，抽样不保证捕获瞬时峰值。

用户已确认采用 **24 位 DAFSA 格式**，并停止追加测试，32 位保留以便未来增长和对照。32 位没有显著查询收益，加载的小幅差异不足以补偿额外 5.23 MB 词典体积。实际 AAR 的 Java/JNI、资产校验和缓存生命周期也已在手机验证；基准与逐用例观察可通过终端工具复现，详见 [图词典引擎](图词典引擎.md)。长期耗电与真实输入法 UI 调度尚需宿主场景测量。
