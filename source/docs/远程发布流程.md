# 一条命令发布客户端资源

在完整本地项目根目录运行：

~~~sh
python3 scripts/publish_release.py \
  --aar data/android/ipa-graph-full.aar \
  --version v0.0.3-dev \
  --message 'Release v0.0.3-dev'
~~~

把 AAR 路径、版本和提交描述换成此次发布的实际值。AAR 应已完成对应版本的验证；发布脚本负责打包与发布，不替代引擎正确性、兼容性或手机性能验证。调用前先自行提交源码等非 `remote/` 的改动，脚本只暂存并提交 `remote/` 内的发布文件。

脚本自动同步 `remote/source/` 的引擎源码快照，生成该版本 AAR 目录和客户端批次，从 AAR 提取配套 JNI、裸 IPADWG01 v2 词典及来源记录，用 Android SDK D8 将 `classes.jar` 转成最低 API 26 的 `classes.dex`，生成大小、SHA-256 和元数据，更新 `VERSION`、最新产物索引与根 `board-update.json`，校验后导出并推送公开内容。默认客户端批次为 `{version}-client.1`；同一引擎版本需要新批次时用 `--batch v0.0.3-dev-client.2`，已发布批次内容不可覆盖。Rust AAR 旁保留配套 `build-report.json`，脚本会核对其中的 AAR SHA 和 Rust/Android 运行时源码 SHA，防止产物与公开源码不一致。

Git 默认使用本机 macOS 系统代理配置；需要指定代理时在同一命令增加 `--git-proxy http://127.0.0.1:端口`，地址取本机实际值。该选项只影响本次发布，不修改 Git 全局配置。

网络中断或发布失败后，修复报错原因并重跑原命令即可继续；无需手动提交中间文件或填写 SHA。

## 最新目录与历史回滚

发布成功后的 `remote/pre-release/` 只保留当前版本 AAR 目录、新客户端批次及索引。脚本会删除其他旧产物目录，并把删除记录提交到 Git。旧资源仍保存在已发布的历史提交中；旧客户端入口的 `artifactCommit` 固定原资源提交，后续清理最新目录不会改变它的下载内容。需要回滚时，从对应已发布提交恢复资源及入口，保留原 SHA 和校验值。

[IPA引擎发布规范通知.md](IPA引擎发布规范通知.md) 保存客户端合同原文，不改写历史通知。产物保留策略以当前流程为准：最新目录只留当前产物，历史由 Git 保存，取代旧通知中保留历史产物目录的约定。引擎与词典版本仍独立；词典内容和哈希未变时，不因引擎升级而改词典版本。

## 自动发布顺序与范围

调用者只运行上述一次命令。脚本内部先提交、校验并推送完整产物，取得实际已发布的公开提交 SHA；再把它写入 `artifactCommit`，单独提交、校验并推送 `board-update.json`。客户端由固定分支的根入口发现更新，按 `artifactCommit` 下载全部匹配资源。无需手动 prepare、subtree split、填写 SHA 或执行第二次推送。

| 项目 | 固定约定 |
| --- | --- |
| 完整本地项目分支 | `codex/ipa-engine-v0.0.1-dev`。 |
| 本地公开导出分支 | `codex/remote-v0.0.1-dev`，只含 `remote/` 的导出历史。 |
| GitHub 目标 | `public/codex/ipa-engine-v0.0.1-dev`；分支名不随版本变化。 |
| 客户端更新入口 | 远程根目录 `board-update.json`。 |

GitHub 仓库只接收 `remote/` 子目录：`remote/README.md` 在远程显示为根 `README.md`，`remote/board-update.json` 显示为根入口。公开内容包括 `source/` 引擎源码、构建及离线编译工具、手写测试和编译产物。未处理原始数据、观测 SQLite 库、采集目录、模型权重、私有报告、缓存和完整项目历史留在本地。

`scripts/sync_public_sources.py` 与公开导出校验共用逐文件白名单；不能因为扩展名是 `.rs`、`.py` 或 `.json` 就自动公开。新增引擎依赖时须明确添加白名单项。脚本拒绝符号链接、缺失源码及白名单外的运行时编译输入，仅替换 `remote/source/`，不清理产物。可用 `python3 scripts/sync_public_sources.py` 单独更新源码快照。快照包含逐文件 SHA、整个源码清单摘要及 Android 构建使用的运行时摘要，产物的 `release.json` 记录对应摘要；同一产物提交固定其源码与二进制。公开源代码不代表已经选定软件许可证，当前不授予项目级许可证；编译词典继续携带各来源声明。

公开快照以 Rust 为生产运行时和图最小化工具，Python 负责离线词条筛选、词频关联及二进制装配。旧 C++ 引擎用于迁移对照。克隆公开仓库后在 `source/` 运行构建和合成测试，完整词典可使用已发布的压缩产物；重新编译词典需自行提供符合 schema 的已筛选观测库。脚本校验导出树及全部导出历史，并只以明确 refspec 推送公开导出分支。

发布不会推送完整项目分支，不使用 force、`--all` 或 `--mirror`，也不创建或更新 `main`。校验、历史映射或普通推送失败时按报错处理，不强制覆盖远程。未来向远程 `main` 合并时，仅在公开仓库中使用 `git merge --no-ff` 或 GitHub **Create a merge commit**，保留合并记录，不使用 fast-forward、squash 或 rebase。
